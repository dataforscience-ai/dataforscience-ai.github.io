Agentic Systems · Microsoft Copilot Studio
Resourcing & Delivery Intelligence AgentIn use
Portfolio and delivery queries against an enterprise resourcing model — used by a global team
Problem

Portfolio-level resourcing decisions required querying a Power BI semantic model that stakeholders couldn’t reach directly. Project-status queries were slow, ad-hoc, and inconsistent across the leadership team — the wrong latency for weekly capacity calls.

Learning

The platform’s native natural-language layer fabricated values on multi-step queries — unusable for decisions with financial consequences. The hardest work wasn’t the agent, it was source-of-truth reconciliation across tables where operational status conflicted with authoritative status.

Build

Microsoft Copilot Studio agent generating deterministic queries against the resourcing semantic model, with an explicit authoritative-source layer that resolves stale-vs-current conflicts. Governance embedded from day one: query logging, source-of-truth mapping, and role-scoped access.

Reflection

Teach the agent which table to trust and it earns audit confidence; skip that step and it’s just another hallucination surface. The moat is the reconciliation layer, not the model.

Next

In use by the wider global team. Version 2 in build — extending along the request lifecycle from querying the resourcing model to feeding request gathering and impact analysis upstream. Moving from reporting agent to workflow agent embedded in the delivery process.

Agentic Systems · Claude Enterprise + Anthropic MCP
Unified Clinical Trial Analytics AgentGovernance review
Reference architecture: collapse a multi-dashboard workflow into a single traceable prompt
Problem

Answering a single clinical-trial operations question — site status, protocol deviations, SDV progress, patient screening reconciliation — required stakeholders to open four to six dashboards and reconcile manually. Multi-day turnaround for questions leadership wanted answered inside a meeting.

Learning

Reconciliation logic across lakehouse tables mattered more than natural-language phrasing. The value wasn’t the prompt — it was collapsing a five-dashboard analyst workflow into one traceable query with full audit lineage.

Build

Claude Enterprise agent via Anthropic MCP running deterministic DAX against the CAM lakehouse semantic model. Governance embedded as design constraint, not review layer: query logging, model cards, and regulatory mappings from day one.

Reflection

Recognized by Anthropic in a customer innovation forum as a reference pattern for multi-source regulated analytics. External validation from a platform partner is a different kind of signal than internal award recognition — it travels.

Next

External sharing under governance review — the work is credible enough that formal review for cross-organization sharing is warranted, not deflected.

Agentic Systems · GraphQL + Cortex + Claude
Digital Teammate for Email AutomationProduction
Self-service enterprise email agent — from ticket-driven customization to platform
Problem

Enterprise email workflows were already automated, but every new use case required roughly a week of developer customization to onboard — making the platform ticket-driven, not self-service. The ceiling on adoption was the delivery model, not the technology.

Learning

The path to production in a regulated environment isn’t the LLM — it’s the sanctioned data-access layer. When the platform’s SQL endpoint was deprecated in the environment, GraphQL became the mandatory integration surface. Building on the sanctioned path was faster than negotiating around it.

Build

Three-layer architecture — GraphQL as sanctioned data access, Cortex as orchestration, Claude as the reasoning layer. Co-built with an architecture lead and an agent-layer engineer to embed governance from day one rather than retrofit at productionization.

Reflection

The value wasn’t sending more emails — they were already automated. The value was eliminating the ~1-week customization cycle every new use case previously required, converting a ticket queue into a self-service capability. Sequence the sanctioned-path work ahead of the agent work and productionization becomes a promotion, not a rebuild.

Next

In production — operated by 2 developers, reaching ~3,000 recipients through ~6,000 automated emails per month. Evaluating extension to adjacent workflows on the same sanctioned data layer.

Governance · Process Design
Governance Framework After a Change-Management GapRatified
Converting an incident into systemic controls — workstream-level CRs, training, and ALM separation
Problem

An automated notification workflow was modified in production without going through the approved change-management process. Second occurrence in a short window. Standard response would have been individual accountability — but the pattern suggested a process-design gap, not misconduct.

Learning

The right frame for a governance leader is systemic, not personal. Two similar incidents from different developers is a signal that the process itself makes the wrong thing easy and the right thing hard. Fixing the person doesn’t fix the pattern.

Build

CAPA framework covering: workstream-level change-request definitions, formal change-management training embedded in developer onboarding, a fast-path CR tier for low-risk edits, environment separation via ALM, and post-implementation CAPA-effectiveness monitoring.

Reflection

This is what AIGP training operationalizes in practice — turning incident response into systemic control uplift with measurable follow-through. The individuals involved were participants in the fix, not the fix.

Next

Framework in effect. Workstream-level change controls, developer training, and ALM environment separation adopted. CAPA-effectiveness monitoring underway.
